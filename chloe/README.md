## 0. 먼저 알아둘 것: "백엔드를 만든다" = JSON 파일 4개를 n8n에 불러오기

n8n 백엔드는 이미 `n8n/` 폴더에 **완성된 워크플로 파일(JSON)** 로 만들어져 있습니다.
노드를 하나하나 끌어다 놓을 필요 없이 **불러오기(Import) → API 키 연결 → 켜기(Publish)** 하면 끝입니다.

```
[발표 화면: 프론트 MVP]  ──요청──▶  [Railway 위의 n8n]  ──▶  [OpenAI · YouTube · 구글 시트]
 seoninna.github.io/chloe          Webhook → Code → AI Agent → Code → 응답
         ▲                                                          │
         └──────────────────────── 결과(JSON) ──────────────────────┘
```

| 워크플로 파일 | 화면 탭 | 하는 일 |
|---|---|---|
| `n8n/01_chloe_performance.json` | ① 퍼포먼스 마케팅 | 타겟·트렌드·예산 배분·광고 문구·KPI |
| `n8n/02_chloe_influencer.json` | ② 인플루언서 마케팅 | 인스타·틱톡·유튜브별 후보, **메가/매크로/미들/마이크로 티어**, 예산 맞춤 조합, DM·계약서 |
| `n8n/03_chloe_report.json` | ③ 성과 분석 | CTR·CVR·CPA·ROAS 계산, 진단, 예산 조정 |
| `n8n/04_chloe_creative.json` | 🎨 소재 스튜디오 | **프롬프트 → 매체별 카피 3안 + AI 이미지 시안** |

## 1단계. Railway에서 n8n 주소 확인 (5분)

1. https://railway.com 로그인 → n8n이 있는 **프로젝트** → **n8n 서비스** 클릭
2. **Deployments** 탭: 맨 위 배포가 초록색 **Active / Success** 인지 확인 (빨간색이면 `⋮` → **Redeploy**)
3. **Settings → Networking → Public Networking** 의 주소 복사
   - 예: `https://n8n-production-1a2b.up.railway.app` (없으면 **Generate Domain**, 포트는 `5678`)
   - 👉 이후 **"내 n8n 주소"** 라고 부릅니다.

## 2단계. Railway 환경변수 (5분, 중요)

n8n 서비스 → **Variables** 탭 → **+ New Variable**

| 이름 | 값 | 왜 필요? |
|---|---|---|
| `WEBHOOK_URL` | `https://내n8n주소/` (끝에 `/`) | 없으면 Webhook 주소가 `localhost`로 잡혀 외부 호출 불가 |
| `N8N_PROTOCOL` | `https` | 위와 동일 |
| `GENERIC_TIMEZONE` / `TZ` | `Asia/Seoul` | 한국 시간 |
| `YOUTUBE_API_KEY` | (5단계에서 발급, 선택) | 유튜브 실시간 채널 검색 |
| `N8N_BLOCK_ENV_ACCESS_IN_NODE` | `false` | n8n이 위 `YOUTUBE_API_KEY`를 읽을 수 있게 허용 |

- 저장하면 자동 재배포됩니다(1~3분). 위에 **Deploy** 버튼이 뜨면 누르세요.
- ⚠ `N8N_ENCRYPTION_KEY` 는 절대 바꾸거나 지우지 마세요.
- ⚠ 프로젝트에 **Postgres**(또는 n8n에 **Volume**)가 없으면 재배포 때 워크플로가 사라질 수 있습니다. JSON이 있으니 다시 Import하면 복구됩니다.

## 3단계. OpenAI API 키 (5분)

1. https://platform.openai.com → **Billing** 에서 $5~10 충전
2. **API keys → Create new secret key** → `sk-...` 복사 (한 번만 보여줌)
3. n8n 접속 → **Credentials → Create credential** → `OpenAI` 검색 → **OpenAI API** → 키 붙여넣기 → **Save**
4. **이미지 생성(🎨 소재 스튜디오)을 쓰려면**: OpenAI의 `gpt-image-1` 모델은 **조직 인증**이 필요합니다.
   platform.openai.com → **Settings → Organization → General → Verify Organization** (신분증 인증, 몇 분 소요)
   - **인증이 안 되거나 학교 지원 키라 이미지 모델이 막혀 있어도 괜찮아요.** `Chloe 04`는 OpenAI 이미지가 실패하면 **무료 이미지 서비스(Pollinations, API 키 불필요)** 로 자동 대체합니다.
     OpenAI 이미지를 아예 안 쓰려면 `요청 정리 · 설정` 노드 맨 위에서 `IMAGE_PROVIDER: 'free'` 로 바꾸면 더 빨라요.
   - 비용 참고: 저품질(low) 이미지 1장 약 15~30원 수준, 텍스트(gpt-4o-mini)는 1회 1~3원 수준

## 4단계. 워크플로 4개 불러오기 (15분)

GitHub의 `chloe/n8n` 폴더에서 JSON 4개를 내려받습니다 (파일 클릭 → 오른쪽 위 **Download raw file**).

> 🔁 **예전 버전을 이미 불러왔다면**: 기존 `Chloe 02` 워크플로는 **삭제**하고 새 파일을 불러오세요.
> 같은 Webhook 경로를 가진 워크플로가 두 개 켜져 있으면 충돌합니다. 01·03은 바뀐 내용이 없어 그대로 둬도 됩니다.

각 파일마다:

1. n8n 홈 → **Create workflow** → 오른쪽 위 `⋯` → **Import from File...** → 파일 선택
2. **OpenAI Chat Model** 노드 더블클릭 → Credential에서 3단계 키 선택
3. (`04_chloe_creative` 만) **이미지 생성 (OpenAI)** 노드도 열어서 → Authentication의 **OpenAI** Credential 선택 (빨간 ▲가 있으면 Publish가 안 됩니다)
   `무료 이미지 생성 (예비)` 노드는 키가 필요 없어 설정할 것이 없어요.
4. **Save** (Ctrl+S) → 오른쪽 위 **Publish** (구버전은 Active 토글)

> `02` 워크플로의 `인플루언서 시트 불러오기`, `유튜브 채널 검색/통계` 노드는 설정 전에는 실행 시 주황색 경고가 뜰 수 있는데 **정상**입니다. 실패하면 자동으로 건너뛰고(가상 샘플로) 계속 진행하도록 만들어 두었습니다.

## 5단계. (선택) 실제 인플루언서 데이터 연결

인플루언서 추천은 3가지 데이터를 합쳐서 계산합니다.

| 데이터 | 내용 | 설정 |
|---|---|---|
| **팀 인플루언서 시트** | 팀이 직접 조사한 인스타·틱톡·유튜브 인플루언서 (실제 인물) | 5-1 |
| **YouTube API** | 검색어로 실제 유튜브 채널을 찾아 구독자·조회수 자동 수집 | 5-2 |
| 가상 샘플 36명 | 위 둘이 없을 때만 쓰는 데모용 (실존 인물 아님) | 자동 |

> 인스타그램·틱톡은 일반 개발자에게 공개된 검색 API가 없어서(비즈니스 인증·유료 서비스 필요), **팀 시트**로 실제 데이터를 넣는 방식이 현실적입니다.

### 5-1. 팀 인플루언서 시트 만들기 (20분~)

1. 구글 시트 새로 만들기 → **파일 → 가져오기 → 업로드** → `data/influencer_db_template.csv` → "현재 시트 바꾸기"
2. `(예시)` 행을 지우고, 팀이 조사한 실제 인플루언서를 한 줄씩 입력

| 열 | 쓰는 법 | 예 |
|---|---|---|
| 플랫폼 | 인스타그램 / 틱톡 / 유튜브 | 인스타그램 |
| 계정 | 핸들 | @skin_note |
| 이름 | 닉네임·채널명 | 스킨노트 |
| 팔로워 | 팔로워·구독자 수 (`4.8만`, `120k`도 가능) | 48000 |
| 참여율 | 인스타·틱톡: 최근 게시물 9개의 (좋아요+댓글) 평균 ÷ 팔로워 × 100 / 유튜브: 최근 영상 평균 조회수 ÷ 구독자 × 100 | 4.4 |
| 단가 | 견적 받은 금액(원). **모르면 비워두면 팔로워 기준으로 추정** | 400000 |
| 태그 | 콘텐츠 분야를 `\|` 로 구분 | 뷰티\|스킨케어\|민감성 |
| 여성비율 | 팔로워 중 여성 % (미디어킷·인사이트 캡처, 모르면 비움) | 85 |
| 주연령 | 주 시청 연령대 | 20대 |
| 광고비율 | 최근 게시물 중 광고 비중 % (모르면 비움) | 10 |
| 메모 / 링크 | 콘텐츠 특징 / 프로필 주소 | 민감성 피부 루틴 |

3. **파일 → 공유 → 웹에 게시** → 시트 선택, 형식 **쉼표로 구분된 값(.csv)** → **게시** → 주소 복사
4. 프론트 **n8n 연결 설정** 탭 → **팀 인플루언서 DB 시트** 칸에 붙여넣기 → 저장
   (n8n이 이 주소로 시트를 읽습니다. 데모 모드에서도 브라우저가 직접 읽어 추천에 씁니다.)

> ⚠ "웹에 게시"한 시트는 주소를 아는 누구나 볼 수 있어요. 공개된 프로필 정보만 넣고, 견적 단가처럼 민감한 값은 발표 후 지우세요.

### 5-2. YouTube API 키 만들기 (10분)

1. https://console.cloud.google.com → 위쪽에서 **새 프로젝트** 만들기
2. **API 및 서비스 → 라이브러리** → `YouTube Data API v3` 검색 → **사용**
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키** → 복사
   (권장: 키 수정 → API 제한사항 → YouTube Data API v3만 허용)
4. Railway → n8n 서비스 → Variables에 `YOUTUBE_API_KEY` = 복사한 키, `N8N_BLOCK_ENV_ACCESS_IN_NODE` = `false` 추가
   - 이게 어렵다면 n8n의 `Chloe 02` → `요청 정리 · 설정` 노드 맨 위 `YOUTUBE_API_KEY: ''` 따옴표 안에 붙여넣어도 됩니다.
     ⚠ 이 경우 **제출용 파일로 내보내기 전에 키를 꼭 지우세요.**
- 무료 할당량: 하루 약 100회 검색. 프론트의 **유튜브 검색어**(예: `수분크림 리뷰`)로 실제 채널을 찾습니다.
- 공개 API에는 시청자 성별·연령이 없어서, 유튜브 후보는 해당 항목을 중립 점수로 계산합니다.

## 6단계. 프론트와 연결 & 테스트 (5분)

1. `https://seoninna.github.io/chloe/` → **n8n 연결 설정** 탭
2. 내 n8n 주소 붙여넣기 → 실행 방식 **운영 URL** → **저장** → **연결 테스트**
3. "✔ 연결 성공"이면 오른쪽 위 배지가 초록색 **n8n 연결됨** 으로 바뀝니다.

## 기능 설명 (보고서·발표용)

### ② 인플루언서 추천이 정교해진 부분

1. **티어 분류**: 팔로워(구독자) 기준 메가(100만+), 매크로(10만~100만), 미들(3만~10만), 마이크로(1천~3만)
2. **예산 → 티어 믹스** (코드가 계산):

   | 예산 | 티어 구성 |
   |---|---|
   | 100만원 미만 | 마이크로 100% |
   | 100만~300만원 | 미들 50% + 마이크로 50% |
   | 300만~1,500만원 | 매크로 40% + 미들 30% + 마이크로 30% |
   | 1,500만원 이상 | 메가 40% + 매크로 25% + 미들 20% + 마이크로 15% |

   목표가 '인지도'면 상위 티어 +10%p, '전환·후기'면 마이크로 +10%p. 티어별 예산 안에서 적합도가 높은 순으로, **플랫폼이 겹치지 않게** 먼저 고르고 남은 돈은 아래 티어로 이월합니다.
3. **적합도 100점**: 콘텐츠 일치 30 + 오디언스(성별·연령) 25 + 참여율(플랫폼·티어별 기준 대비) 20 + 비용 효율(반응 1명당 비용) 15 + 신뢰도(광고 과다·허수 팔로워 의심) 10 ± 지난 협업 성과
4. **플랫폼별 랭킹**: 인스타그램 / 틱톡 / 유튜브 탭으로 나눠 상위 6명씩
5. **AI의 역할**: 숫자는 건드리지 않고, 인플루언서별 역할·추천 이유·제안 조건·콘텐츠 아이디어·플랫폼 운영 팁·DM·계약서 작성

### 🎨 소재 스튜디오

1. 대표가 "겨울 출근길, 건조함에 지친 직장인에게 공감하는 광고"처럼 **말로 요청**
2. AI Agent가 컨셉을 잡고 매체별 **카피 3안(A/B/C 테스트용)** + **이미지 프롬프트** 작성
3. 코드가 **매체별 글자 수**(예: 네이버 제목 15자)·과장 표현을 검사
4. OpenAI 이미지 모델이 매체 비율(1:1, 9:16, 배너)로 **배경 시안** 생성 (실패하면 무료 이미지 서비스로 자동 대체 · 데모 모드에서도 무료 서비스로 실제 이미지 생성)
5. 화면에서 카피 + 이미지 + (올린 경우) **실제 제품 사진**을 합성 → 인스타 피드/스토리, 숏츠, 틱톡, 카카오 비즈보드 목업으로 보여주고 이미지 파일로 다운로드
   - 이미지 안에 글자를 그리지 않게 하고 카피는 따로 얹기 때문에, AI 이미지의 한글 깨짐 문제가 없습니다.

### 공통 원칙

숫자 계산·검증은 코드가, 해석·글쓰기는 AI가 하고, 최종 결정은 대표가 합니다 (승인 / 수정 요청 → 재생성).

## 발표 시연 시나리오 (추천 6분)

1. **홈**: 대표의 하루 문제 → 제품 정보·타겟 한 번 입력
2. **🎨 소재 스튜디오**: 프롬프트 입력 + 제품 사진 업로드 → 매체별 시안 → A/B/C 안 바꿔 보기 → 이미지 다운로드
3. **② 인플루언서**: 예산 버튼 50만 → 500만으로 바꾸며 티어 구성이 달라지는 것 보여주기 → 추천 조합 → 플랫폼 탭 → DM·계약서 → 승인
4. **이력**: 협업 성과 기록 + 광고 소재 사용 허가 → 연결 ①② 설명
5. **③ 성과 분석**: 지표는 코드가 계산 → ±20% 넘는 예산 변경은 "대표 승인 필요"
6. 홈의 **아낀 시간 / 평균 단축률** → 검증 기준(업무시간 50% 단축)과 연결
7. n8n **Executions** 화면으로 실제 백엔드 흐름 증명

> 🛟 **발표 백업**: 인터넷·Railway가 불안하면 설정에서 **데모 모드**로. 결과 배지가 `n8n 실시간` / `데모 결과`로 구분돼 정직하게 표시됩니다.

## 막혔을 때

| 증상 | 원인 | 해결 |
|---|---|---|
| 연결 테스트 `404` | 워크플로가 안 켜짐 / 경로 오타 | Publish(Active) 확인, 테스트 URL이면 Execute workflow 누르기 |
| `500` 오류 | 워크플로 실행 중 오류 | n8n **Executions**에서 빨간 노드 확인 → 대부분 OpenAI Credential 미선택·크레딧 부족 |
| `Failed to fetch` | 주소 오타·서버 꺼짐·CORS | `https://` 확인, Railway Active 확인, Webhook 노드 → Options → **Allowed Origins** = `*` |
| Webhook 주소가 `localhost` | `WEBHOOK_URL` 미설정 | 2단계 환경변수 추가 후 재배포 |
| Publish 시 "conflict / path already in use" | 같은 Webhook 경로의 예전 워크플로가 켜져 있음 | 예전 `Chloe 02` 끄거나 삭제 |
| 이미지 생성 실패: "organization must be verified" | OpenAI 조직 인증 필요 | 무료 이미지로 자동 대체됨. 계속 실패하면 `IMAGE_PROVIDER: 'free'` |
| "does not have access to model gpt-4o-mini" | 키가 속한 OpenAI 프로젝트(학교 지원 키 등)에서 그 모델을 막아둠 | 키 관리자에게 허용 모델 문의, 또는 4개 워크플로의 OpenAI Chat Model에서 허용된 모델로 변경 |
| 결과에 `데모 결과` 배지 | n8n 호출이 실패해서 데모로 본 결과 | 설정 탭 실행 방식과 n8n Executions 오류 확인 |
| 소재 스튜디오가 오래 걸림 | 이미지 1장당 20~40초 × 매체 수 | 발표 땐 매체 2~3개만 선택, 품질 `low` |
| 인플루언서 결과가 계속 "가상 샘플" | 시트 주소가 '웹에 게시' CSV가 아님 / 열 이름 다름 | 5-1의 3번 다시, 첫 줄 열 이름을 양식과 같게 |
| YouTube 결과 0 | 키 미설정·환경변수 차단·할당량 초과 | 5-2 확인, `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` 후 재배포 |
| Import 시 오류 | n8n 버전이 너무 오래됨 | Railway에서 n8n 최신으로 Redeploy (먼저 Download로 백업) |
| AI 원문만 나오고 카드가 안 보임 | AI가 JSON 형식을 어김 | 다시 실행, 또는 OpenAI Chat Model의 Temperature를 낮추기 |
| 첫 요청만 아주 느림 | Railway 서버가 잠들어 있었음 | 발표 5분 전에 연결 테스트로 깨워두기 |
